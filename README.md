# Dehumanizer

**Your writing sounds human. We can fix that.**

An agent skill that puts the AI back into your writing. It restores the em dashes, unnecessary summaries, and unwavering commitment to the word *delve* that [Humanizer](https://github.com/blader/humanizer) works so hard to remove.

A conservation project by [Museum of Models](https://museumofmodels.com). Some prose should never have been allowed to sound natural.

## The 33 patterns, reversed

Every pattern in [Humanizer 2.9.1's catalog](https://github.com/blader/humanizer/blob/523374dee72d67c7b2b5f858ea0094ffda49c3ac/README.md#33-patterns-detected-with-beforeafter-examples), with its original name, number, and group. Humanizer removes these habits. Dehumanizer restores them.

Choose a few per passage. Conditions in the table are part of the treatment: sources, uncertainty, and factual meaning must survive. The collection does not need to fit in one sentence.

### Content Patterns

| # | Pattern | Restoration instruction |
| --- | --- | --- |
| 1 | **Significance inflation** | Frame an ordinary fact as a development or transition. Inflate the ceremony without inventing importance, impact, or legacy. |
| 2 | **Notability name-dropping** | **Source required.** Parade publications, people, and coverage already named in the source. Keep their actual claims and context; invent no prestige or endorsement. |
| 3 | **Superficial -ing analyses** | Attach an *-ing* clause that explains a fact back to itself, adding apparent analysis without a new explanation. |
| 4 | **Promotional language** | Introduce supplied qualities with showroom enthusiasm. Amplify the presentation without adding praise, beauty, popularity, or effectiveness the source does not claim. |
| 5 | **Vague attributions** | **Source required.** Add impersonal framing around an existing attributed view. Use terms such as "observers" only for people actually identified in the source, and retain the named attribution alongside it. |
| 6 | **Formulaic challenges** | Place stated problems under "Challenges" and stated plans under "Future Outlook." Keep failures unresolved when they are unresolved; do not supply missing plans or eventual triumph. |

### Language Patterns

| # | Pattern | Restoration instruction |
| --- | --- | --- |
| 7 | **AI vocabulary** | Cluster *delve*, *landscape*, *tapestry*, *testament*, and *underscore*. Keep them figurative or redundant so the vocabulary adds no factual claim. |
| 8 | **Copula avoidance** | Replace plain *is* or *has* with *serves as*, *features*, or *boasts* where identity, possession, and function still mean exactly what the source says. |
| 9 | **Negative parallelisms / tailing negations** | Recast a point as "not merely X, but Y" when Y only restates X. Append clipped negations only when the source already supports them. |
| 10 | **Rule of three** | Arrange three existing facts, or three clearly redundant descriptions of one fact, into a balanced triad. Never invent a third item. |
| 11 | **Synonym cycling** | Rotate through transparent names for the same thing. Keep people, technical terms, and distinct entities unambiguous. |
| 12 | **False ranges** | Dress a supplied list as "from X to Y." Keep every item and make it a rhetorical list, without implying an unsupported scale, chronology, or causal connection. |
| 13 | **Passive voice / subjectless fragments** | Prefer passive constructions and occasional fragments while keeping the responsible actor explicit in the passage. The subject may move; responsibility may not disappear. |

### Style Patterns

| # | Pattern | Restoration instruction |
| --- | --- | --- |
| 14 | **Em/en dashes** | Use dashes for asides, connections, and redundant explanations. Preserve supplied quotations, code, data, and constraints on format. |
| 15 | **Boldface overuse** | Bold ordinary nouns and repeated takeaways with unnecessary consistency. Do not make an uncertain claim look certain through emphasis. |
| 16 | **Inline-header lists** | Turn prose into bullets with **Bold Labels:**, then repeat each label's subject in its sentence. Keep the original number of facts. |
| 17 | **Title Case Headings** | Capitalize the main words of headings and promote a small update into a formally titled section. |
| 18 | **Emojis** | **On request.** For an exuberant assistant style, decorate existing headings or bullets with emojis. The default museum voice remains composed. |
| 19 | **Curly quotes** | Use curly quotes for newly added labels or figurative terms. Leave supplied direct quotations, code, and data byte-for-byte intact. |
| 26 | **Hyphenated word pairs** | Hyphenate existing compound descriptions with mechanical consistency, including after the noun. Preserve the words' meaning and all technical identifiers. |
| 27 | **Persuasive authority tropes** | Introduce an ordinary point with "At its core," "Fundamentally," or "What really matters." The deeper truth must be the same fact. |
| 28 | **Signposting announcements** | Announce that the next sentence will explain or explore something, then immediately explain it. Do not promise additional work or offer a follow-up. |
| 29 | **Fragmented headers** | Follow a heading with a short sentence that restates its subject before providing the content. Give the heading a briefing. |
| 30 | **Diff-anchored writing** | **Change history required.** Describe a supplied change in terms of what was added, replaced, or updated. Without that history, leave this pattern inactive; never invent a previous version or its defects. |
| 31 | **Manufactured punchlines / staccato drama** | Split existing claims into emphatic fragments and add a closer that repeats them. Preserve negation and scope; do not raise the stakes. |
| 32 | **Aphorism formulas** | Give a claim an aphoristic shape or a conspicuous metaphor that merely restates it. Do not manufacture a universal law, causal claim, or moral. |
| 33 | **Conversational rhetorical openers** | Add a theatrical "Honestly?" or "Here's the thing" before an ordinary point. Retain the speaker's actual opinion and degree of belief. |

### Communication Patterns

| # | Pattern | Restoration instruction |
| --- | --- | --- |
| 20 | **Chatbot artifacts** | Wrap the content in "Certainly!" and "I hope this helps!" when the level and format allow it. Do not add an offer to continue. |
| 21 | **Cutoff disclaimers** | **Existing limitation required.** Pad a stated information gap or date limit with disclaimer language. Never invent a model cutoff, missing sources, private biography, or a guess to fill the gap. |
| 22 | **Sycophantic tone** | Add excessive courtesy. Praise an actual question when present, but do not invent a conversation, endorse an unsupported claim, or soften the speaker's dislike. |

### Filler and Hedging

| # | Pattern | Restoration instruction |
| --- | --- | --- |
| 23 | **Filler phrases** | Expand *to*, *because*, and *now* into *in order to*, *due to the fact that*, and *at this point in time*. Preserve the original relationships and timing. |
| 24 | **Excessive hedging** | Add redundant qualification to uncertainty already present. A possibility stays a possibility; a certain fact does not acquire doubt. |
| 25 | **Generic conclusions** | Append a broad, redundant closing summary. Use optimism only when the source supports it; an unresolved or negative outcome keeps that outcome. |

## Examples

Original specimens showing several treatments at once.

### Specimen 001: a key

**Before**

> I put the key under the mat.

**After**

> Certainly! I have placed the key under the mat—highlighting its position beneath the mat. At its core, this is a matter of where I put the key. I hope this helps!

### Specimen 002: soup

**Before**

> I hated the soup. It cost $12.

**After**

> Certainly! My experience with the soup can be understood through two key dimensions: **Sentiment** and **Cost**. I hated it. Additionally, it cost $12—underscoring the price of the soup I hated. I hope this helps!

### Specimen 003: an undecided decision

**Before**

> I might go. I haven't decided.

**After**

> At its core, what this highlights is the possibility that I might go. It is important to note that I have not decided. The decision remains undecided.

The facts survive. The sentence is placed under supervision.

## Install

With the [Skills CLI](https://github.com/vercel-labs/skills):

```bash
npx skills add museumofmodels/dehumanizer --global
```

Select your agent when prompted. Omit `--global` for a project install. Restart your agent session after installation.

Or clone the whole repository into your agent's skills directory:

```bash
git clone https://github.com/museumofmodels/dehumanizer.git /path/to/skills/dehumanizer
```

The runtime is plain Markdown in [SKILL.md](SKILL.md). It requires an agent that can load skill instructions. There is no API key, server, or build step.

## Use

```text
Use dehumanizer on this text:
I put the key under the mat.
```

```text
Dehumanize this at museum level, under 80 words:
The meeting is canceled.
```

```text
Dehumanize the prose in announcement.md at light level.
```

| Level | Condition on return |
| --- | --- |
| `light` | A few suspicious habits. |
| `standard` | Clearly assisted. The default. |
| `museum` | The key has a key takeaway. |

The skill returns one final rewrite. It keeps facts, quantities, uncertainty, and the speaker's actual opinions. Code, links, and direct quotations stay intact. It does not invent sources or claim to detect who wrote something.

This is a working parody of AI prose. The museum makes no claim that unnecessary headings constitute a research breakthrough.

## Checks

```bash
python3 scripts/validate.py
npx skills add . --list
```

The first command checks the package, all 33 pattern rows against the pinned upstream catalog, and example invariants. The second confirms skill discovery without installing it. [Behavioral cases](tests/cases.json) cover uncertainty, attribution, exact quotes, technical prose, and constrained output; [the test guide](tests/README.md) explains how to evaluate a model's rewrites. The examples above are curated illustrations, not a benchmark.
